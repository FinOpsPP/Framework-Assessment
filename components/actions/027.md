# 27: Analyze Root Causes & Fix Issues

**Specification Version:** 2.0.0

**Status:** Accepted

**Slug:** 27-analyze-root

**Implementation Types:**

* None

## Descriptive Statement

Analyze root causes; fix tags, allocation rules, or usage issues.

## Supplemental Guidance

The order is not negotiable. An unowned anomaly is not analyzed, an undiagnosed anomaly cannot be
classified, and a cause that was never classified cannot be shown to recur. Teams that jump to item 4
tend to fix the same anomaly repeatedly without noticing.

A root cause taxonomy does not need to be elaborate to earn item 3. Categories such as deployment change,
rate or commitment change, organic usage growth, allocation or tagging defect, and third party change are
enough to make the counts useful.

Item 4 asks for the cause to be fixed, not the symptom. Suppressing an alert, raising a threshold, or
granting a standing exception closes the ticket without meeting this item.

## Scoring Guide

**Weight:** 1.0

### Formula

1. Assign each recorded anomaly to an accountable owner with a due date for the analysis
2. Document a root cause for each anomaly that names the change which triggered it
3. Classify root causes against a consistent taxonomy so causes can be counted across periods
4. Remediate the cause rather than the alert, and record the fix and its verified effect on spend
5. Convert recurring causes into a preventive control: a policy, guardrail, budget, or detection rule

10*Ceil(x/5)
