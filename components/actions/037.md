# 37: Establish Forecasting Approach

**Specification Version:** 2.0.0

**Status:** Accepted

**Slug:** 37-forecast-approach

**Implementation Types:**

* None

## Descriptive Statement

Establish "why," approach (simple/trend/driver-based), cadence, and horizon.

## Supplemental Guidance

The items are unordered because an organization can arrive at a documented approach from any direction.
Most teams already have a method in use and have simply never written down why they chose it.

Cadence is deliberately absent from this list. How often a forecast is refreshed is the frequency scored
by action 39, and scoring it twice would double count a single practice. This action scores the decision
to have set one, alongside the horizons and granularity that action 39 defines but does not score.

More than one forecast is normal and expected. A commitment purchase forecast and an annual budget
forecast answer different questions over different horizons, and each is scored against these items.

Item 4 is where most reconciliation disputes begin. A forecast that quietly excludes amortized commitment
cost, credits, or shared cost will not reconcile to an invoice no matter how good the method is.

## Scoring Guide

**Weight:** 1.0

### Formula

* State why each forecast exists and which decision it supports, such as a budget, a commitment, or a plan
* Name the method in use for each forecast: run rate, trend, driver based, or a hybrid, and why it fits
* Define the time horizon each forecast reaches, the backwards horizon it draws on, and its granularity
* Define what is in scope, including commitments, credits, taxes, and shared costs
* Record the inputs and assumptions each forecast depends on, along with the owner of each one
* Set an accuracy tolerance for each forecast and the action taken when it falls outside that tolerance
