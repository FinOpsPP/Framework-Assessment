# 103: Publish Guidelines & Guardrails

**Specification Version:** 2.0.0

**Status:** Accepted

**Slug:** 103-publish-guideline

**Implementation Types:**

* None

## Descriptive Statement

Publish guidelines, guardrails, and automation controls.

## Supplemental Guidance

This is a threshold rather than a sequence because organizations reach enforcement by different routes.
A platform team that ships a policy as an admission control rule on day one has preventive guardrails
without ever having written the reference architecture, and should not be penalized for the order.

Score against the policy set as a whole. Where different policies sit at different levels, use the level
that covers the majority of policies by the spend they govern, not by policy count.

The step from 4 to 6 is the largest real jump in this action. Everything below it depends on somebody
choosing to read the guidance, and everything at or above it does not.

Preventive guardrails only earn score 8 when the exception path from action 102 actually works. A block
with no sanctioned way around it gets routed around instead, usually through an account nobody governs.

Score 10 is the "policy as code" end state. The published rule and the enforced rule come from the same
source and ship together, so the two can no longer drift apart between reviews.

## Scoring Guide

**Weight:** 1.0

### Formula

None

### Scoring Details

**Score Type:** threshold

| Score | Condition |
| ----- | --------- |
| 0 | Policy exists but is not published anywhere practitioners work |
| 2 | Published as readable guidance in a discoverable, single location |
| 4 | Guidance paired with worked examples, reference architectures, or templates teams can copy |
| 6 | Detective guardrails report violations automatically against the published guidance |
| 8 | Preventive guardrails block non-conforming changes at deploy time, with an exception path |
| 10 | Guardrails maintained as code beside the policy, versioned and released with it |
