# 35: Report Estimate Accuracy

**Specification Version:** 2.0.0

**Status:** Accepted

**Slug:** 35-report-accuracy

**Implementation Types:**

* None

## Descriptive Statement

Report estimate accuracy; enforce variance thresholds by maturity.

## Supplemental Guidance

The denominator counts only estimates whose actual cost is known. An estimate for work that has not
run yet cannot be right or wrong, and including it would make the number move whenever the pipeline
changed rather than when accuracy did.

A wide threshold makes this number look excellent. A practice allowing fifty percent variance will
sit near 100% and have learned nothing, so the figure is only meaningful next to the threshold it
was measured against. Action 30 defines the estimating scope and policy constraints, including that
threshold, and the two should be read together.

The capability expects the threshold to tighten as a practice matures. Its Crawl tier accepts
estimates that are not especially granular or accurate, its Walk tier expects higher accuracy
organizationally, and its Run tier expects an explicit range and confidence level rather than a
single number.

Action 34 chooses which scenarios are estimated and action 40 compares the forecast against actuals.
This action measures whether the estimates themselves came true.

## Scoring Guide

**Weight:** 1.0

### Formula

x = Estimates whose actual cost landed inside the variance threshold set for them
y = All estimates made whose actual cost is now known

x / y
