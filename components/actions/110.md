# 110: Automate Chargeback Data Flows

**Specification Version:** 2.0.0

**Status:** Accepted

**Slug:** 110-automate-chargeback

**Implementation Types:**

* None

## Descriptive Statement

Automate data flows and chargeback runs; minimize manual effort.

## Supplemental Guidance

This is a threshold rather than a bucket because the stages replace one another. A practice posting
automatically into finance tooling is not also maintaining the spreadsheet, so asking it to tick the
lower rungs would measure history rather than maturity.

The gap between stage 2 and stage 5 is where most practices sit. Tooling
that produces a figure somebody then edits in a spreadsheet is not automation, because the edit is
where the errors and the delay both live.

Stage 10 keeps exceptions routed for review on purpose. Full automation that silently posts whatever
it computes is not the top of this ladder, since a chargeback nobody can intercept is one a cost center
disputes after the fact instead of before.

Action 109 scores the documented design of the chargeback, and action 111 scores distributing the
output and tracking what happens to it. This action scores only how the run itself is produced.

## Scoring Guide

**Weight:** 1.0

### Formula

Scored at the highest stage the chargeback run reaches. A practice does not need the stages below it,
because a run integrated into finance tooling has already replaced the spreadsheet it grew out of.

### Scoring Details

**Score Type:** threshold

| Score | Condition |
| ----- | --------- |
| 0 | Assembled in spreadsheets and posted by manual journal entry |
| 2 | Centralized tooling produces the figures, which are then exported and edited by hand |
| 5 | The run is automated end to end and a person posts the result |
| 7 | The run posts to the financial system, with a person reviewing before release |
| 10 | Chargeback and showback reporting is integrated automatically into finance tooling, with exceptions routed for review |
